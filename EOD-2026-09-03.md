## Shipped

**Excel report.** New month-by-month workbook available next to the PDF on every report. Rebuilt from the saved reports on each download rather than stored, so it can't drift — one column per month, appended automatically as new reports are generated.

- Rows follow the country and landing-page selection made in the report editor, so the sheet and the PDF always describe the same set
- Each month's figures come from that month's own report, so a country selected for the first time this month still gets its history filled in
- A month with no data for a row shows a grey em-dash, never a misleading zero
- Styled to match the dashboard — blue header, banded rows, print-ready

**Report download is now a dropdown.** "Standard Report" (PDF, behaviour unchanged) and "Excel Report".

**Report email now takes both.** Checkboxes for PDF and Excel, PDF ticked by default. Tick both and they go as one email with two attachments, or as two separate emails if preferred. An Excel-only send skips the PDF render entirely, so it's much faster.

**Project name is editable.** Added to the Edit project dialog with validation — rejects empty and over-long names, trims before saving.

**Search Console setup simplified.** The property picker, spinner and status lines are gone. You type the domain; the property is matched behind it. One grey line appears only when it can't be matched.

**Month labels.** Reports list and editor headers now read `Aug 2026` instead of `2026-08`.

## Security audit and fixes

Full pre-deploy review of both the backend and frontend. **No critical findings. No auth holes, no SQL injection, no secrets in git history.** Authorization was clean across all 43 routes; XSS surface was clean and well designed.

Everything found was fixed:

| Severity | Issue | Fix |
|---|---|---|
| High | Login throttle keyed on IP+email, so it could never actually lock — password spraying across many accounts tripped nothing | Added a per-account counter underneath, deliberately looser so it can't be used to lock real users out |
| Medium | Live temporary passwords and OTPs printed to the server log in outbox mode | Prints the redacted copy |
| Medium | 2FA backup codes survived a re-invite, leaving an old second factor working | Codes deleted on re-invite; endpoint now checks enrolment |
| Medium | Raw Google API errors returned to users, naming the service account and GCP project | Logged in full, fixed message returned |
| Low | Excel formula injection — a cell label could become executable in the client's Excel | Labels forced to text |
| Low | Password reset on an invited account left it permanently unrecoverable | Reset now reactivates the account |
| Low | `pypdf` carried 6 CVEs | Bumped to 6.16.1 — dependency scan now clean |

**Also removed:** the "Data gaps" footer in the Excel workbook was printing raw Google errors — full request URLs and the service-account identity — into a file that gets emailed to clients. It was the only path by which that detail left the team.

**`.gitignore` hardened.** Secret rules were pinned to one exact filename, so a rotated service-account key, a `.env.local`, or any `.pem` would have been committed. Now pattern-based.

## Live issues diagnosed

**Sattva retreat — no Search Console data.** The property `thesattva.com` was there and the service account had access; the project just never picked it up. A project resolves its property when created or saved, and nothing re-resolves it in between — so access granted afterwards is never noticed. Widened the repair script to fill in blank projects; fixed by running it.

**school of Dharama — no Search Console data.** Genuine permission gap: `schoolofdharma.com.au` is not among the 17 properties the service account can read. Needs the bot added in Search Console.
